## What is in this build

Completes the 0.1.50 fix, which only covered half the problem.

- **The version check now guards every path to the update banner**
  (`fix(update): guard the version check on every path`). 0.1.50 put the check on
  our own `updatefound` listener — a deploy landing while the page is open.
  Workbox raises `onNeedRefresh` from a **second** situation as well: its
  `waiting` event, which fires when a worker is *already* waiting at
  registration, left over from an earlier visit and surfaced on the next load.

  That path never reached the check. Reported from a phone: reloading onto
  0.1.51, with „Über die App" correctly showing 0.1.51, still produced a banner
  offering an update to 0.1.51 — because a worker from an earlier deploy was
  sitting in `waiting`.

  The check now lives in `onNeedRefresh`, the single funnel both paths reach, and
  the redundant `updatefound` listener is gone. Workbox attaches its
  `controlling` reload listener *before* calling `onNeedRefresh`, so declining to
  set the flag does not break the „Aktualisieren" button for the cases that do
  warrant a banner.

## Why 0.1.50 missed it

It was verified by deploying a new version to an open session — which exercises
`updatefound` and nothing else. The leftover-worker case only appears when a
worker survives *between* visits, so reproducing it needs a deploy, then a
reload, not a deploy into an open page. The phone hit it immediately; the desktop
test could not.
