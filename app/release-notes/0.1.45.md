## What is in this build

A single fix, for an error 0.1.44 itself caused.

- **The SPA fallback no longer answers `/data/` requests** (`1ebdc69`, web and
  native). On the first load after the 0.1.44 deploy — before pressing
  "Aktualisieren" — the app showed:

  ```
  Laden fehlgeschlagen: Unexpected token '<', "<!doctype "... is not valid JSON
  ```

  0.1.44 renamed the climate rasters (`precip_*` → `preciphyras_*`, `et0_*` →
  `et0fao_*`). A client still running the **previous** service worker asked for
  the old names, and the Workbox `NavigationRoute` had **no denylist**, so the
  miss was answered with `index.html` at **HTTP 200**. The loader's `if (!r.ok)`
  guard therefore passed and `r.json()` failed on `<!doctype` — an error that
  reads like a corrupt file when the actual cause is a stale cache.

  Three changes, root cause first:
  - `navigateFallbackDenylist` in `vite.config.ts` excludes the data directory, so
    a missing raster returns a genuine 404. Built from `base`, so it survives
    `VITE_BASE_PATH`.
  - `rasterData.ts` rejects an HTML payload even at HTTP 200 and names the cause,
    instead of letting `JSON.parse` produce the message above.
  - The splash error offers a **Neu laden** button that unregisters the service
    worker, purges the caches and reloads. A plain F5 cannot fix a stale worker —
    the worker has to go first — which is why the only way out was previously the
    "Aktualisieren" banner.

## Note on the rollout

Deploying this does **not** retroactively help a client that still carries the
0.1.44 worker: that old worker is the one answering the request. Such clients hit
the error once more on their next visit and then recover — now with a button that
explains what to do. From the 0.1.45 worker onward the denylist applies and the
error cannot recur.

The heavier alternative, `SW_KILL=1` (see `vite.config.ts`), would clear every
client's worker in one deploy but forces a full re-download for everyone. Not
worth it for a one-time error that now has a visible recovery path.
