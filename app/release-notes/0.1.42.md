## What is in this build

Two user-facing changes since 0.1.41:

- **Summary totals no longer report mm/a** (`1b5493d`). The project totals divided
  summed m³/a by summed field area, but golf's mm/a is referenced to its irrigated
  sub-areas (greens/tees/fairways, Table 35 — 20.57 ha on a 45 ha course), not to
  the field. Mixing the two denominators let the total come out below every
  individual row. Totals now show m³/a only; per-assignment mm/a stays, with a
  footnote on golf naming its reference area. Applies to the on-screen summary and
  the PDF. Reported by a tester on 2026-08-07.
- **Hint on choosing the nFKWe class for heterogeneous fields** (`e65d667`). The
  class comes from a single map click, so on a field spanning several soil units it
  is close to arbitrary while feeding straight into the water demand. A new
  collapsible in the field form suggests sampling several spots, reading off the
  spread, and then setting a representative class by hand — the tester's own
  proposal. Same feedback thread.

Everything else in this version is developer tooling and does not affect the app:

- `20643a9` build: the Android build reads signing passwords from a gitignored
  `keystore.properties`
- `09a8c0a` chore: internal documentation moved to a private companion repository
- `11a26a0` fix: build scripts locate the JDK/SDK instead of hardcoding paths
